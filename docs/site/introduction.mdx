Tell the agent what you need to do. Connect researches an integration, prepares
its configuration, and asks you to approve the software and access it needs.
Toolkit supplies more than 100 adopted OSS identities plus acquisition tools
for supported Python, Node and MCP packages outside the catalog.

## Start with the work

A request such as "Read last week's updates from these channels and summarize
them" gives the agent a goal without requiring you to choose a package or
protocol. The catalog speeds up known choices; it does not limit research.

The first release supports two service-setup paths:

- **Standalone CLI:** choose the realm, review setup and access, then use the
  installed integration through an ordinary `rkat` agent in that realm.
- **Integrated Console:** begin in your application's original conversation.
  Its setup panel collects protected input and reviews, then returns the result
  to the same task.

Model-provider sign-in and integration-account sign-in are separate. Keep keys,
passwords and authorization codes out of chat. Installing software does not by
itself connect an account or give every agent access.

## What the first release covers

Service support follows each integration's declared operations, authentication
profile and platform. More than 100 adopted identities does not mean every
provider operation or newcomer authentication route is qualified.

Broad frontend, custom-host, remote, HomeCore and device parity remains
[follow-up work](/roadmap). Existing frontend and SDK components keep their
explicit host contracts. A frontend needs a persistent application that owns
identity, audience, routing and delivery; a one-shot CLI session is not that host.

Connect is optional. Core and Meta can use existing tools without it. Connect
uses their public APIs and introduces no Toolkit dependency into `rkat`.
The [advanced host recipes](/guides/host-composition) explain application
composition separately from the [ordinary quickstart](/quickstart).

The first Connect release delivers the service-integration path through the
standalone CLI and integrated Console after the matching Core/Meta release is
ready. It keeps the adopted OSS library and agent-led acquisition beyond that
library as the two central capabilities.

This release boundary is narrower than the full product end state. Unfinished
frontend, custom-host, remote and device work is deferred explicitly rather than
blocking every service user or being described as complete.

## First-release priorities

- More than 100 adopted OSS identities with exact supported platform, operation
  and authentication profiles.
- Agent-led research and setup through the supported Python, Node and MCP forms.
- Standalone setup followed by fresh ordinary `rkat` use in the selected realm.
- Integrated Console setup that returns to the original task through its native owner.
- Honest cancellation, refusal, uncertain-outcome and shutdown results.

The repository's first-release plan records the exact remaining release work.
Publication and final native consumer
acceptance remain pending; use [availability](/availability) for current download
status and [quickstart](/quickstart) for the supported user paths.

## Follow-up work

Broad frontend and custom-host adoption, remote deployments, HomeCore, Reachy and
OB3 parity, and all-provider newcomer authentication remain follow-ups. Existing
implemented components and accepted checks remain available within their actual
scope; they do not imply that every host or account is ready.

The repository's follow-up ledger keeps the incomplete Toolkit and platform
requirements, their owners and evidence limits. REST and outer-MCP Connect entry
surfaces remain deferred while MCP integrations remain in scope.

## End state

The full target still includes durable service and frontend use, account and
resource permissions, audience policy, custom integrations and host-selected
deployment. A frontend must own real admission, routing and delivery through a
compatible persistent application. Meerkat owns native execution and grants;
Meta owns application composition. Connect consumes those public contracts.

No catalog count, fixture pass or installer exit alone proves that a user can
finish a task. Each released claim needs the matching installed consumer and
actual result, while follow-up scope keeps its own completion criteria.

## Publication status

The first public Meerkat Connect 0.9.0 release is being prepared against released
Meerkat Core and Meta 0.9.0. **Public Connect downloads are not available yet.** Existing
private library prereleases and staged verification prefixes retain their exact
inputs and limits; they are not the first released CLI or Console experience.

The [release roadmap](/roadmap) separates this release from the follow-up work.
Product users review the installation and access they authorize.

## First-release service paths

| Path | User flow | Support boundary |
| --- | --- | --- |
| Standalone Connect CLI | Install the complete platform archive, choose a realm, set up a service, then use ordinary `rkat` in that realm | Matching native release and complete bundled resources; current native grants and credentials still govern every operation |
| Integrated Console | Use an application with Connect enabled, complete protected setup, and return to the original conversation | The application owns login, admission, original-task continuation and lifecycle; a gateway binary alone is not an application |
| Adopted OSS library | Select a supported integration and its documented account/configuration profile | 101 adopted identities on macOS and 100 on Linux, excluding Playwright on Linux; only the declared operations and profiles are covered |
| Acquisition outside the catalog | Let the agent research a supported Python, Node or MCP package and propose exact setup | Canonical source, package, launch and effect validation plus explicit access review; arbitrary packages and provider accounts are not promised to work |

The [quickstart](/quickstart) describes the user steps. Release notes will list
only the actual qualified platform assets and their checksums. The current
packaging profiles are Apple Silicon macOS 13.5 or later and Linux x86_64 with
glibc 2.39. An available packaging profile is not a claim that its final release
artifact has already passed acceptance.

Installation, account connectivity, grants and successful use remain distinct.
A successful component test, account redirect or setup response does not establish
a completed business task. Public release claims must follow the actual matching
consumer result.

## Advanced and deferred use

Existing frontend, SDK and host components remain available under their stated
contracts. They are useful for application authors and preserve their accepted
component evidence. The first release does not claim broad frontend, custom-host,
remote, HomeCore, Reachy or OB3 parity, nor every provider's newcomer sign-in flow.

Upgrading an existing nonempty MobKit 0.8 application store through an
authoritative Meta 0.9 startup is deferred when its composition manifest has
only the legacy `created_by_mobkit` writer field. Meta 0.9 expects
`created_by_meta` and can refuse that manifest before startup. This specific
application-store limit does not describe fresh Meta 0.9 Console installations
or Core realm/session use through the Connect CLI.

A frontend requires a compatible persistent application that owns participant
identity, audience, routing and reply delivery. A CLI setup conversation does not
create that host. See [frontend setup](/guides/setup-a-frontend) and
[host composition](/guides/host-composition) for those explicit contracts.

Rust and JSON-RPC with Python/TypeScript clients are the native composition
surfaces. REST and outer-MCP Connect entry points remain deferred. MCP servers
used as integrations are included. The [roadmap](/roadmap) distinguishes these
follow-ups from the first release; they are not silently removed from the end state.

## Distribution

Use the [public Connect release list](https://github.com/lukacf/meerkat-connect/releases)
for selected assets, hashes and release status. This source export is prepared
for Connect 0.9.0; preparing source does not establish that a release has been
published or that a registry package is available.

Historical private library prereleases and their raw evidence are not included.
The [advanced installation guide](/library/local-install) retains their component
instructions with explicit historical labels. Their manual host preparation is
not an ordinary Connect installation requirement.

The coordinated native dependencies are Core and Meta 0.9.0. Toolkit package
names remain `meerkat-toolkit`, `@rkat/toolkit` and `meerkat-connect`; this release
uses version 0.9.0 for the main product surfaces. Independent adopted component
versions and immutable historical catalog identities retain their existing values.
A GitHub source release does not by itself publish those packages to PyPI, npm or
crates.io.

Review each selected artifact's bundled licenses and upstream notices before
redistribution. The nine extracted HomeCore-derived Python modules are licensed
under MIT OR Apache-2.0, with their provenance retained in `LICENSE-HomeCore`.
Other components and optional dependencies retain their own license terms.

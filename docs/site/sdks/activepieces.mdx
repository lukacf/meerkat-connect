## Configure the MCP server

Use the exact archive and portable consumer lock identified by `docs/adoption/ACTIVEPIECES-SUPPORT.md`. The complete suite is verified on Node 24.19.0/macOS, with a bounded follow-up on the declared minimum Node 22.19.0. Rebuilding mutable source creates a new artifact requiring its own checks. No published npm package is assumed.

Start with `profiles` and `config-help --profile tally.get-form` on the installed
CLI. The [account prerequisites](/library/local-install#select-an-account-through-the-host)
adds profile-specific `prerequisites` and `unresolved_details` for all 63 profiles.
For example, WordPress needs an application password, Supabase's selected admin
path needs a service role key, and S3 uses explicit matching signing credentials.
Configuration contains the environment variable name; the host supplies its
secret value. These commands need no existing
configuration or credential and perform no provider login or refresh.

Save a nonsecret configuration file:

```json
{
  "profile": "tally.get-form",
  "token_env": "TOOLKIT_TALLY_TOKEN"
}
```

Run `check-config --config /absolute/path/tally.json` before supplying its
credential. A passing check validates configuration, not account access.
Configure the host to supply the selected token in that exact environment variable and launch the installed `meerkat-toolkit-activepieces-mcp` executable with:

```text
serve --config /absolute/path/tally.json
```

`describe --config /absolute/path/tally.json` prints the selected tool schema without credentials or provider calls. `serve` requires the explicitly named token. NocoDB also requires `origin` and numeric `version` (3 or 4). Asana selects `asana.get-task`. Manual resource IDs are tool inputs; credentials remain host configuration. The server acquires no OAuth connection and runs no dynamic dropdown callbacks.

Jotform requires `region` set to `us`, `eu` or `hipaa`, with no fallback between endpoints. Both IDs are digit strings. Brevo supports a selected contact identifier type and returns `found:false` on a real HTTP 404 only after response cleanup; authentication and service failures remain errors.

Contacts returns one bounded search page; Figma reads comments; Acuity returns one bounded appointment list. The exact schemas and artifact-frozen guide define input limits and selected fields.

MailerLite reads one campaign and requires its record envelope. Calendly reads one event selected by ID or an exact supported provider URI. All three expose one read and preserve their actual donor result; they do not perform subscriber enumeration, campaign sending or scheduling-link creation.

Google Tasks requires exact selected list/task IDs and preserves optional response fields while checking the returned task identity. Campaign Monitor uses its selected key as the Basic-auth username and returns a miss only for HTTP 404 after cleanup; its actual repeated custom-field transformation remains. Okta additionally requires `origin` and searches one page using a literal ASCII email. Help Scout requires at least one filter, treats subject/email as literal values and exposes provider search syntax only through the explicit `query` field. It returns the first matching conversation from one page. Okta and Help Scout responses are limited to 200 records; no schema supplies mutation-only arguments for reads.

The preceding eight profiles read one selected resource, except Toggl's explicitly bounded project page. Notion returns page metadata and properties, not body blocks. WordPress uses its default REST view and excludes subdirectory installations. Intercom requires an explicit region. The artifact-frozen configuration guide states exact lexical bounds and response identity checks. ## Use the reader API

Install the reviewed local archive with its retained consumer lock in the consuming host. No published npm package is assumed.

```typescript
import { createReader } from "@rkat/toolkit-activepieces";

export function selectedFormReader(apiKey: string, hostFetch: typeof fetch) {
  return createReader({
    profile: "tally.get-form",
    auth: { apiKey },
    transport: hostFetch,
    timeoutMs: 10_000,
    maxResponseBytes: 1_048_576,
  });
}
```

`describe()` returns the selected input schema without contacting a provider. `invoke(inputs, {signal})` executes the selected donor behavior and returns detached JSON. Credentials are captured when the reader is created and are never tool arguments. Create a new reader when the host changes its selected connection.

The host supplies an already authorized account and transport. This API does not acquire or refresh OAuth credentials, invoke dynamic property lookups, register tools or determine permission.

## Select writes explicitly

`createReader` accepts only read profiles. The separately named `createWriter` API and explicitly configured MCP write profiles expose these four selected operations:

| Write profile | Existing host credential and binding | Selected effect |
| --- | --- | --- |
| `activecampaign.create-contact` | HTTPS origin and API key | Create a contact with explicitly supplied custom fields |
| `freshservice.create-ticket` | Domain and API key | Create a ticket for a selected requester |
| `gitea.create-issue` | HTTPS origin, token, owner and repository | Create an issue in the selected repository |
| `datadog.submit-log` | Site and API key | Submit a log for processing |

The host chooses the write profile and credential in configuration; tool arguments cannot switch a reader to a writer. Each write permits one request, with no automatic retry, replay, refresh, compensation or deduplication promise. A pre-entry failure is `not_attempted`; any failure after transport entry remains `uncertain`, including cancellation, malformed/lost responses and cleanup failure. Datadog success acknowledges `accepted_for_processing`, not downstream completion. Host authorization and any business reconciliation remain the host's responsibility.

## Transport and lifetime

The transport must obey the exact URL, headers, method, abort signal and redirect refusal, with normal TLS and no automatic replay. Each invocation has its own donor factory and transport closure. Concurrent accounts share no mutable credential or transport slot.

The deadline covers sending and response reading. Cancellation signals the host, joins the actual request and awaits body cleanup. A host implementation that ignores cancellation can delay settlement. The adapter bounds response bytes and JSON structure and refuses unexpected redirects, malformed bodies and HTTP failures with safe metadata.

**Adopted local library profile.** Toolkit reuses the official GitHub MCP server unchanged for three useful reads. Separate macOS arm64 and Linux x86_64 binaries use the same revision `85598ba6e1256f7ebf4867b95d63b833c4549264`. This profile assumes an existing selected token. First-time authentication and native agent-led installation remain [unfinished](/availability).

## Install through an existing setup agent

The current [local library archives](/library/local-install) offer official
GitHub setup on macOS arm64 and Linux x86_64. Follow the selected archive's
README to enable `official-github` with its platform-specific official bundle,
installer and optional verifier pins. This route remains manually selected;
the new catalog handoff index covers the adapter libraries and services.

The agent reads the catalog, chooses profile `selected-reads`, selects all three
operations below and supplies only the variable name
`GITHUB_PERSONAL_ACCESS_TOKEN`. Metadata preparation, validation, installation
and file checks never run GitHub or acquire a token. The installer copies the
binary and all 78 notices, then emits the fixed GitHub.com read-only command.
The host separately supplies credentials and controls the whole child environment.

An exact install replay observes the same job. A fresh recovery process can
check the saved original request without retrying installation or restoring
historical success. Actual ordinary MCP trials exercise both paths and reject
altered notices and launch configuration. The Linux setup successor separately verifies offline bootstrap, installation,
exact replay and fresh-process recovery from its archive.

## Configure a standard MCP host

Launch the selected binary over stdio with:

```text
stdio --read-only --gh-host https://github.com --tools get_me,list_commits,get_file_contents
```

The account owner supplies a token with the intended repository access. The host passes it to this process as `GITHUB_PERSONAL_ACCESS_TOKEN`, outside model arguments and checked-in configuration. Use one process per selected account. Changing accounts requires retiring the previous process.

Provide a controlled child environment. The server reads `GITHUB_*` settings, so unrelated toolset, feature, application, OAuth, logging or proxy variables must not leak into the child. `--read-only` matters because its upstream default is false. Confirm the three observed tools after connecting. A tool list selects operations; GitHub token permissions determine which repositories they can read.

| Tool | Use |
| --- | --- |
| `get_me` | Observe the authenticated account profile. |
| `list_commits` | Read one requested repository page with valid positive integer `page` and `perPage` values. |
| `get_file_contents` | Read a selected repository path, preferably at a known commit SHA. |

## Retain process ownership

Apply a finite caller deadline. MCP cancellation stopped the held fixture request and the same session recovered, but signal handling does not guarantee that every server handler joins internally. Keep ownership until actual process exit and cleanup. The accepted tests observed provider connection EOF and OS reaping; cancelling an awaiter alone is insufficient.

## Understand the supported limits

The unchanged server has a known pagination schema/runtime mismatch: it advertises page ranges without enforcing all of them. It can pass through more rows than requested and has no general response-byte cap. A large-file resource link is presentation behavior, not a memory bound.

Provider errors can reflect credentials. Redirects can access other destinations; host/port credential scoping does not guarantee TLS on every hop. File-reference resolution and tree fallbacks can make additional requests. The host must assess these properties before activating the profile for its workload. They are documented limits, not hidden guarantees supplied by Toolkit.

The original macOS acceptance uses 14 tests through a fresh official MCP client, fabricated accounts and loopback provider responses. It verifies the exact source/build evidence, useful reads, failures, account isolation, recovery and process retirement. It does not establish live account access, OAuth, hosted transport or native Meerkat/MobKit attachment. The full evidence and support disposition are in `docs/verification/20261003-github-mcp/` and `docs/adoption/GITHUB-SUPPORT.md`.

The macOS consumer delivery separately copies and verifies two fresh
